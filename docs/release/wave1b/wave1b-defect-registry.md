# Wave 1B Defect Registry (Part W)

Every real issue found and fixed during Wave 1B, with a stable ID. All are fixed unless marked otherwise.

| ID | Area | Summary | Severity | Status |
|---|---|---|---|---|
| REL-001 | Windows installer | `/SUPPRESSMSGBOXES` auto-answers `MsgBox` with its default button, so a silent/scripted uninstall would have auto-confirmed both "delete my data?" prompts and permanently deleted business/patient data with no user interaction. | High (silent data loss) | **FIXED** -- `if UninstallSilent() then Exit;` added as the first statement in `InitializeUninstall()`, both `.iss` files. |
| REL-002 | Android build | `signingConfigs {}` declared after `buildTypes {}` in both `build.gradle` files (pre-existing since inception, never triggered because no real `keystore.properties` had ever existed before this wave). Groovy's top-to-bottom evaluation meant `buildTypes` referencing `signingConfigs.release` failed once a real keystore config existed. | Medium (blocked release signing) | **FIXED** -- `signingConfigs {}` moved before `buildTypes {}`, both files. |
| REL-003 | Signing credentials | PowerShell 5.1's `-Encoding utf8` writes a UTF-8 BOM, corrupting a saved 32-character keystore password file (35 bytes instead of 32) relative to the password actually used to encrypt the keystore. | High (would have caused permanent key loss if unnoticed) | **CAUGHT AND FIXED** before any real use -- byte-count check found it; both keystores (seconds old, zero real usage) regenerated with BOM-free encoding and immediate keytool self-verification reading the password back from the file. |
| REL-004 | Signing credentials | Windows backslash paths written into `keystore.properties` with quadruple-escaped backslashes were corrupted by Java's `.properties` parser (`\r` consumed as a literal escape, silently eating characters from the path). | Medium (blocked release build) | **FIXED** -- rewritten using forward slashes, which Java/Gradle accept natively on Windows. |
| REL-005 | Android lint | `lintRelease` failed with 3 `RestrictedApi` errors on `MainActivity.dispatchKeyEvent` -- a known androidx lint-metadata false positive (overriding the public `android.app.Activity.dispatchKeyEvent`, not calling a restricted internal API). Blocked `lintRelease` and would have blocked CI/Play-publishing gates that run `lintVitalRelease`. | Low (build-blocking, not a real vulnerability) | **FIXED** -- scoped `@Suppress("RestrictedApi")` with an explanatory comment. |
| REL-006 | Windows launcher | **Cross-product port race**: both launchers tested a port with a throwaway socket, released it, then bound for real later (TOCTOU gap); Windows additionally doesn't guarantee exclusive port ownership on `bind()` without `SO_EXCLUSIVEADDRUSE`. Launching Retail and Clinic within milliseconds of each other could result in both silently "listening" on port 5000, with Windows routing connections to either process unpredictably -- confirmed for real via `netstat`/`curl` (Retail's own readiness log claimed success on a port that was actually answering as Clinic). | High (real cross-product data-exposure risk under a realistic launch-timing scenario) | **FIXED** -- both launchers rewritten to bind-and-hold a live socket (`SO_EXCLUSIVEADDRUSE` set) and hand it directly to waitress, closing the race at the source; added a defense-in-depth `/api/version` product-identity check as a second layer; regression test added (`test_bind_free_socket_holds_the_port_exclusively`); both exes and both installers rebuilt and re-verified from the fixed source. See `build-and-test-gates-report.md` for the full narrative. |
| SEC-001 | Retail receipt (Windows) | The first draft of the print-receipt button embedded `JSON.stringify(saleData)` directly into an inline `onclick` HTML attribute -- a real injection risk (an admin-entered product name containing a quote/HTML character could break out of the attribute context). | Medium (XSS-class) | **CAUGHT AND FIXED** immediately, same edit session, by an automated security-review hook -- sale data stored on `this._lastSaleData`, button references it by name only, nothing interpolated into attribute text. |
| DATA-001 | Retail receipt (Windows) | The pre-existing on-screen receipt popup mixed the server's authoritative `saleData` with `payload` (client-submitted) and `this._cart` (client's local state) for the displayed Total and line items -- same bug class as the earlier wave's MOB-001 (client value silently standing in for the server's authoritative one). | Medium (not exploitable in the current single-tender-type flow, but a real violation of the authoritative-data principle) | **FIXED** -- `_showReceipt` and `_printReceipt` now read exclusively from the real server response. |
| LOC-001 | Clinic Android | `AppRoot.kt`'s `NavigationDrawerItem` labels for "Patients" and "Billing" (and, on the second pass, "Doctors"/"Lab Expenses"/"Prescriptions", the AI-sheet `_suggestions` list, and the send-icon content description) were never wrapped in `tr()` -- missed by the automated `HardcodedStringAuditTest` because it initially scanned only `ui/screens/*.kt`, not `AppRoot.kt`. Found only via real-device testing, reported directly by the user. | Low (cosmetic, but a real, user-visible localization gap) | **FIXED** -- all wrapped in `tr()`; `HardcodedStringAuditTest`'s `targetFiles()` extended to also cover `AppRoot.kt` so this class of gap can't recur silently. |
| HW-001 | Retail Android | No UI existed to change the app's language on Android (Windows had one; Android did not) -- reported directly by the user ("i cant option where to change language on retailapp"). | Low (feature gap, not a defect in existing code) | **FIXED** -- language switcher added to `RetailSettingsScreen` (mirrors Clinic's existing pattern). |
| TEST-001 | Python test harness | Running the full pytest suite in a single process caused cross-test-file state pollution: multiple test files each set the same environment-variable-derived module-level constant (`AURA_APP_DATA`), and Python's `sys.modules` caching meant the first file's setting silently leaked into later files. Root-caused via `git stash` proof to be a test-harness artifact only -- zero production impact, since real deployments only import each module once per process. | Low (test-only, no runtime impact) | **FIXED** -- `products/run_all_tests.py` runs each test file as its own subprocess for full isolation, without altering any production module-level path-resolution code (per this wave's explicit instruction not to change production behavior merely to make tests pass). |

## Not a defect (investigated and confirmed correct)
- `android:exported="true"` on `MainActivity` in both manifests -- required for a launcher activity's `MAIN`/`LAUNCHER` intent-filter, not a vulnerability. No other component is exported in either manifest.

## Severity legend
High = real risk of data loss, data exposure, or permanent credential/key loss if unnoticed. Medium = real correctness/security issue with a bounded blast radius under current usage patterns. Low = build-blocking, cosmetic, or test-harness-only, no runtime user impact.
