# Wave 1B Residual Risk Register

What is *not* covered by Wave 1B, carried forward honestly rather than hidden. This phase is not allowed to hide limitations -- this document is where they are recorded.

| Risk | Impact if it materializes | Current mitigation | Disposition |
|---|---|---|---|
| Windows installers/exes are unsigned | SmartScreen "unrecognized publisher" warning on every customer's first run; some customers may distrust or refuse to run it. | `windows-code-signing-guide.md` + `products/sign_windows_release.ps1` are ready to apply a real certificate the moment one is purchased -- no further engineering work needed, just the cert. | DEFERRED -- explicit user choice this wave ("No real certificate"). |
| Windows receipt printing not click-through tested against a real print dialog | If the `window.print()`/iframe mechanism has an environment-specific quirk (driver, popup blocker, WebView2 print-dialog behavior), it would only surface on first real customer use. | Syntax-checked, served-correctly confirmed, field-by-field data-correctness verified against the real API contract. | DEFERRED TO WAVE 1C (no interactive session/physical printer available this wave). |
| No direct ESC/USB/Bluetooth thermal printer protocol on either platform | Customers with printers not reachable via a Windows driver, or wanting native Android thermal printing, are not served. | OS-print-spooler (Windows) and share-sheet (Android) cover the common case without needing raw ESC/POS. | DEFERRED TO LATER HARDWARE ADAPTER -- no printer hardware existed to validate a raw-protocol implementation against; shipping one unverified would risk garbled output with no way to catch it before a customer does. |
| No camera-based or serial/BLE/vendor-SDK barcode scanning | Customers without a USB/Bluetooth HID keyboard-wedge scanner (the one supported input method) can't scan barcodes at all. | HID keyboard-wedge covers the dominant real-world scanner category. | DEFERRED TO LATER HARDWARE ADAPTER -- contract exists (`ScannerAdapter.kt`), no hardware to validate an implementation against. |
| Offline/network-loss behavior not explicitly tested this wave | Both products are local-first by architecture (no cloud dependency), so there is no "server unreachable" failure mode in the traditional sense -- but this was not explicitly exercised as a scenario this wave. | Architecture itself is the mitigation (nothing to go offline from). | NOT TESTED this wave, low actual risk given the architecture. |
| Cross-product port race (REL-006) fix verified via source-level simultaneous-launch reproduction, not via the exact installed-exe double-click scenario a real customer would perform | A residual variant of the same race class could theoretically exist if Windows' scheduler behaves differently under real desktop-icon double-click timing versus a scripted near-simultaneous launch. | The fix closes the race at the socket level (not a timing-dependent mitigation) and adds a defense-in-depth product-identity check that turns any residual edge case into a loud, safe failure instead of a silent cross-wire. | LOW RESIDUAL RISK -- fix is structural, not probabilistic; the defense-in-depth layer bounds the worst case. |
| Arabic receipt rendering on a real physical printer | The receipt template is plain HTML/CSS (no canvas/bitmap rendering), so any OS-installed font should render Arabic correctly -- but this depends on the actual printer/driver's font handling, which was not available to test. | Documented as an open item in `receipt-printing-test-report.md`, not claimed as verified. | DEFERRED TO WAVE 1C. |
| No Owner Control Center, licensing, subscription enforcement, telemetry, or auto-updates | Product cannot currently be centrally managed, licensed, or remotely updated. | N/A -- explicitly out of scope for Wave 1B by the spec that governed this wave. | OUT OF SCOPE (not a Wave 1B defect; a deliberate boundary). |

## What this phase explicitly does NOT claim
Per this wave's own instruction: neither product is described anywhere in Wave 1B's documentation as "commercially ready," "production ready," "enterprise grade," "safe for paid customers," or "universally compatible with all scanners or printers." Every claim in this documentation set is scoped to exactly what was built and verified.
