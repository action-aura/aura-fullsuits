## Real finding during this regression — not forced, not hidden

The first Owner run (against the unmodified `b5dd17a` closure candidate)
failed 2 tests:

```
FAILED tests\test_database.py::test_migration_runs_clean_from_empty_database_and_rolls_back
FAILED tests\test_phase6_migration.py::test_upgrade_on_populated_phase5_database_loses_no_records
sqlalchemy.exc.CompileError: Can't emit DROP CONSTRAINT for constraint
ForeignKeyConstraint(...); it has no name; table=Table('owner_product_versions', ...)
```

**Root cause:** migration `96429a63cb29` (M10)'s `downgrade()` was
autogenerated with `op.drop_constraint(None, 'owner_product_versions',
type_='foreignkey')` for two foreign keys created via
`create_foreign_key(None, ...)`. `None` is not a valid constraint name to
drop by. This codebase's own established convention (every other
migration's downgrade, e.g. `3c0d51d82d8c`) hand-fills the real
Postgres-generated name here — this migration's downgrade was never edited
to do that, and because `alembic check` only validates the *upgrade* side
against model metadata, this was invisible until something actually
exercised `alembic downgrade`.

**Fix, and how it was proven (not just asserted):**

1. Queried the real database for the actual constraint names:
   `owner_product_versions_created_by_staff_user_id_fkey`,
   `owner_product_versions_published_by_staff_user_id_fkey`.
2. Filled them into `downgrade()`.
3. Actually ran `alembic downgrade -1` twice (through `86e9229f85c1` → `96429a63cb29` → `13944658bddf`)
   against the real local database, then `alembic upgrade head` back — a
   real round-trip, not a dry-run.
4. Re-ran `alembic check` — drift-clean.
5. Re-ran the two originally-failing test files in isolation — 9/9 passed.
6. Per the explicit instruction to rerun the affected complete suite after
   any source change mid-regression: re-ran the **entire** Owner suite
   from the fixed state — 1,041/1,041, 0 failures.

This is the ninth real bug this phase found and fixed in either
already-shipped or newly-added code — see
`final-residual-risk-register.md`'s closed list for the full nine.
