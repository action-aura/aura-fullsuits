# Phase 9.5E — Expense Numbering

`app/expenses/numbering.py::allocate_expense_number()` reuses the exact `DocumentNumberCounter` table and `SELECT ... FOR UPDATE` + `SAVEPOINT` mechanism Phase 9.5D Milestone 5 already built and proved under a real 12-thread concurrent-allocation race (`docs/owner/phase9_5d/quote-numbering-contract.md`). No new numbering authority was created — `EXPENSE` is simply a new `document_type` value in the same generic counter table, format `EXP-{year}-{seq:04d}`.

Because the underlying mechanism is unchanged from its own proven implementation (same row-lock, same first-allocation-of-the-year `begin_nested()` fallback), this phase relies on Phase 9.5D's own concurrency proof rather than re-running an identical race test against identical code — the only new surface is the `EXPENSE` prefix mapping and call site (`submit_expense()`), which is not concurrency-sensitive by itself (each expense submission independently calls `allocate_expense_number()`, which is where all the real concurrency-safety lives, already proven). A dedicated re-proof is listed as a to-do for Milestone 23's performance/concurrency pass, at real scale, alongside the rest of that milestone's synthetic-data work, rather than duplicated here.
