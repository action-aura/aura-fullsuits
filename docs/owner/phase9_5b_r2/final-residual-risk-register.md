# Phase 9.5B-R2 — Final Residual Risk Register

## Real, documented limitations (none blocking)

1. **44 newly-responsive tables lack `data-label` attributes.** Mobile
   layout genuinely collapses to stacked cards now (the real bug is fixed),
   but stacked values have no "Field: " prefix — a polish gap, not a
   functional break. Follow-up: add `data-label` per column, same pattern
   already used in `employees/list.html`.
2. **`generic_audit_action_label()` does not cover every possible audit
   action code** — an inherently unbounded, growing set. Safe `.get()`
   fallback means this can never crash; only occasionally shows an
   untranslated code. Extend the dictionary as new action codes are
   observed in production.
3. **Notification titles generated by `reconciliation.py`/
   `device_slot_ops.py`/`expiry_scan.py` remain English-only by deliberate
   decision** — these are stored content generated outside guaranteed
   request/locale context (e.g. scheduled jobs); safely translating them
   requires storing structured data and rendering at display time, a real
   architecture change out of this wave's scope. Documented, not silently
   dropped.
4. **Browser/accessibility validation is representative, not exhaustive** —
   5 route families across the 4-viewport matrix, not literally every
   page × viewport × locale combination. Stated explicitly in
   `full-viewport-browser-validation.md` and `owner-wide-accessibility-revalidation.md`.
5. **One pre-existing, isolation-confirmed-passing test-order-dependence
   flake** (`test_terminal_states_reject_further_transitions`,
   `ObjectDeletedError`) — same class as the already-documented Retail
   order-dependence in Phase 9's history. Not a functional regression;
   24/24 passing when the file runs alone.
6. **Bilingual functional-parity real-submission testing covered customer
   creation and two commercial_ops "new" forms specifically** — other
   workflows (payment recording, license-key issuance, backup/restore)
   validated via GET-rendering + the pre-existing 605-test suite, not a
   fresh real-submission Playwright pass this wave.

## Real risks found and already closed this wave (listed for completeness,
   not residual)

The mobile table-collapse defect (44 tables), the four broken creation
forms, the `pybabel update` fuzzy-mismatch bug, the request-context/gettext
architectural bug, and the incomplete audit-action-label set — all found
and fixed, not carried forward. See `rtl-defect-and-fix-log.md`.

## Explicit non-risks (confirmed, not just assumed)

- No stable machine/API/enum value was ever translated (verified by direct
  code review and the API-boundary test suite).
- No authentication/authorization behavior differs by locale (verified: no
  `@require_permission`/`@require_recent_auth` decorator was touched).
- No secret (license key, signing key, MFA secret, session token, pepper)
  appears translated or altered — only surrounding UI text was ever
  translated around them.
- The original legacy `AuraEnterprise` repository was never mutated
  (verified identical entry/exit state).
