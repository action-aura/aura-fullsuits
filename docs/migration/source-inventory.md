This inventory is the Phase 0 deliverable. It documents what exists today and where it will land. No files have been moved, copied, or modified in `SOURCE` as part of Phase 0 — this is pure discovery.

**Important terminology note surfaced during discovery:** the repo contains two unrelated things that both match "clinic/healthcare":
- `api/subsystems/clinic_api.py` + `database/subsystems/clinic.db` (`clinic_bp`, `/api/sub/clinic/*`) — **this is the real "Aura Clinic" product.** Has Android UI, multi-tenant auth, RBAC.
- `api/subsystems/healthcare_api.py` + `database/healthcare.db` (`healthcare_bp`, legacy single-domain) — an unrelated generic "industries demo" module (sits next to `education.db`, `manufacturing.db`, `banking.db`, `cms.db`, `studio.db`) with its own `Health_*` tables. No Android/UI presence, no shared code with Clinic.
This inventory extracts **only the real Clinic product**. The `healthcare_api.py` module is explicitly out of scope — flagged in the risk register.

Also important: **Android is one shared Gradle project producing two product-flavored APKs** (`clinic` / `retail` flavors → `com.actionaura.clinic` / `com.actionaura.retail`), not two separate Android projects. The extraction plan treats it as one `android/` tree with both flavors preserved, matching the existing setup — inventing two separate Android projects would be a rewrite, which is forbidden.
